# SCREENS.md — 미니 트립플래너 화면계획서 (강사 기준선 · 2회차 배포본)

> 1회차 화면설계표(7열)에 **요소 번호**와 **상태**를 더한 화면계획서입니다.
> 요청과 확인은 요소 번호로 합니다. 예: "docs/SCREENS.md의 S01-② 이동수단"
> 2회차 범위: S01 ①~⑥ · S02 ①②④⑥. S02 ③ 지도와 ⑤ AI 설명은 '자리'만 두고 3회차에 채웁니다.

## 화면 목록과 흐름

| 화면 | 이름 | 주소 | 들어오는 길 | 나가는 길 |
|---|---|---|---|---|
| S01 | 조건 고르기 | `/` (첫 화면) | 앱 열기 · S02-⑥ | ⑤ [코스 만들기] → S02 |
| S02 | 오늘의 코스 | `/plan?mode=…&hours=…&themes=…` | S01-⑤ | ⑥ [조건 다시 고르기] → S01 |

흐름: S01 조건 고르기 → ⑤ [코스 만들기] → S02 오늘의 코스 → ⑥ [조건 다시 고르기] → S01

- 조건은 주소(URL)에 담아 넘깁니다. 예: `/plan?mode=car&hours=6&themes=history,food`
- 값 이름: 이동수단 `car` · `transit` / 테마 `history`(역사) · `nature`(자연) · `food`(먹거리) · `activity`(체험) · `cafe`(카페)
- 테마 값은 data/places.json에 들어 있는 값을 그대로 씁니다 (스타터 기준 5개: `history` · `nature` · `food` · `activity` · `cafe`).
- data/places.json에는 6번째 테마 `rest`(16곳)가 더 있지만 **숨깁니다** — S01-④ 칩에 넣지 않고 주소 `themes`로도 받지 않습니다. `rest`만 가진 장소는 없어서 빠지는 장소는 없습니다.

## S01 조건 고르기

**화면 정보** — ID S01 · 주소 `/` · 들어오는 길: 앱 열기, S02-⑥ · 나가는 길: ⑤ → S02

**와이어프레임 (위 → 아래)**

```
┌──────────────────────────────┐
│ ① 미니 트립플래너 · 공주 64곳   │
│ ② 이동수단 (필수 · 하나만)      │
│    [자가용] [도보·대중교통]      │
│ ③ 여행 시간 (필수 · 하나만)     │
│    [3시간] [6시간] [9시간]      │
│ ④ 관심 테마 (선택 · 여러 개)    │
│    (역사)(자연)(먹거리)(체험)(카페) │
│ ⑤ [ 코스 만들기 ]              │
│ ⑥ 이동수단과 시간을 골라 주세요  │
└──────────────────────────────┘
```

**요소 설명표**

| # | 요소 | 보이는 것 | 사용자 행동 | 시스템 반응 | 데이터 |
|---|---|---|---|---|---|
| ① | 머리줄 | 앱 이름 + '공주 64곳' | — | 장소 수를 세어 보여 줌 | `getPlaces()` 개수 |
| ② | 이동수단 (필수) | 자가용 / 도보·대중교통 버튼 2개 | 하나만 고름 | 고른 버튼 강조 · ⑥ 문구 바뀜 | `mode` |
| ③ | 여행 시간 (필수) | 3 · 6 · 9시간 버튼 3개 | 하나만 고름 | 고른 버튼 강조 · ⑥ 문구 바뀜 | `hours` |
| ④ | 관심 테마 (선택) | 역사 · 자연 · 먹거리 · 체험 · 카페 칩 5개 | 여러 개 고름 · 비워도 됨 | 고른 칩 강조 · 비우면 모든 테마 | `themes` |
| ⑤ | [코스 만들기] | 큰 버튼 | 누름 | ②③ 전에는 꺼짐 · 켜지면 조건을 주소에 담아 S02로 | 주소(URL) |
| ⑥ | 안내 문구 | 버튼 아래 한 줄 | — | 필수 전 '이동수단과 시간을 골라 주세요' · 후 '좋아요!' | — |

**상태**

| 상태 | 보이는 것 |
|---|---|
| 처음 (필수 미선택) | ⑤ 꺼짐 + ⑥ '이동수단과 시간을 골라 주세요' |
| 준비됨 (②③ 선택) | ⑤ 켜짐 + ⑥ '좋아요!' |
| 테마 비움 | ⑥에 '테마를 안 고르면 모든 테마로 만들어요' — 오류가 아닙니다 |

## S02 오늘의 코스

**화면 정보** — ID S02 · 주소 `/plan?조건` · 들어오는 길: S01-⑤ · 나가는 길: ⑥ → S01

**와이어프레임 (위 → 아래)**

```
┌──────────────────────────────┐
│ ① (자가용 · 6시간 · 역사 · 먹거리 · n곳) │
│ ② 알아 두세요 · 이동 시간은 추정값이에요 │
│ ③ ┌ 지도 자리 — 3회차 ┐          │
│ ④ 1 · 도착~출발 · 장소 1        │
│       이동 n분(추정)            │
│    2 · 도착~출발 · 장소 2        │
│ ⑤ ┆ AI 설명 자리 — 3회차 ┆        │
│ ⑥ [ 조건 다시 고르기 ]          │
└──────────────────────────────┘
```

**요소 설명표**

| # | 요소 | 보이는 것 | 사용자 행동 | 시스템 반응 | 데이터 | 언제 |
|---|---|---|---|---|---|---|
| ① | 조건 요약 칩 | 고른 조건 + 장소 수 | — | 주소의 조건을 읽어 칩으로 | 주소(URL) | 2회차 |
| ② | '알아 두세요' 배지 | 시간표 위 한 줄 | 읽기 | reason 코드를 문구로: '이동 시간은 추정값이에요' · 영업시간이 없는 장소(기본 시간 적용)가 코스에 들면 '영업시간을 확인해 주세요' | `/api/plan` 응답의 reason | 2회차 |
| ③ | 지도 자리 | 회색 상자 '지도는 3회차에' | (3회차) 마커 클릭 | 3회차: OSM 지도 + 번호 마커, 누르면 이름 팝업 | 코스 장소 좌표 | 3회차 |
| ④ | 시간표 | 번호 · 도착~출발 · 장소 이름 · 구간마다 '이동 n분(추정)' | 읽기 | `/api/plan`이 계산한 순서·시각을 그대로 보여 줌 — 화면은 계산하지 않음 | `/api/plan` 응답 | 2회차 |
| ⑤ | AI 설명 자리 | 점선 상자 'AI 설명은 3회차에' | — | 3회차: 코스와 따로 불러옴 · 실패하면 기본 설명 + ② 배지 | `/api/narrate` | 3회차 |
| ⑥ | [조건 다시 고르기] | 버튼 | 누름 | S01로 돌아감 | — | 2회차 |

**상태 4가지**

| 상태 | 언제 | 보이는 것 | 버튼 |
|---|---|---|---|
| 정상 | 코스가 나옴 | ①②④⑥ + ③⑤ 자리 | ⑥ |
| 불러오는 중 | `/api/plan` 응답을 기다리는 동안 | '코스를 만들고 있어요…' | ⑥ 잠시 꺼 둠 |
| 빈 결과 | 조건에 맞는 코스가 없음 | '맞는 코스가 없어요 — 여행 시간을 늘리거나 조건을 바꿔 보세요' | ⑥ |
| 오류 | 서버 응답 실패 | '잠시 후 다시 시도해 주세요' | [다시 시도] + ⑥ |
| 잘못된 조건 (추가) | 주소를 고쳐 목록에 없는 값이 들어옴 (`/api/plan` 400 · 예: `hours=5`, `themes=rest`) | '조건이 올바르지 않아요 — 조건을 다시 골라 주세요' | ⑥ (다시 시도는 없음 — 결과가 같음) |
